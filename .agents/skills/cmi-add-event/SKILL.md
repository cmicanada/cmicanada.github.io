# Manage CMI Events

## GitHub Issue intake

When the user supplies an Issue number or URL, read [the repository Issue workflow](../../../docs/content-issues.md) before implementing. Read the complete Issue and relevant attachments, use the matching Traditional Chinese form fields as the content brief, and preserve the Issue URL as editorial provenance. Traditional Chinese-only submissions still require complete Simplified Chinese and English delivery. Follow the task’s publication authorization; a form selection alone does not trigger publication.

## Project and source

Work from the root of the current `cmicanada/cmicanada.github.io` checkout. All paths below are relative to that root. The committed `.agents/skills/` version is authoritative for this project. Read its applicable `AGENTS.md`, `README.md`, current `scripts/build.mjs`, `scripts/locales.mjs`, `scripts/validate.mjs`, and relevant `content/site.json` records before editing. Inspect Git status and preserve unrelated work. These mechanics describe the October 2026 implementation; current code takes precedence.

Edit source records and templates, then rebuild; generated root HTML, `/zh-hans/`, `/en/`, search indexes and sitemap are committed outputs. Never maintain the three languages by separately editing generated HTML. Keep Traditional Chinese as the default, the currently approved site logo, 20px body copy, and 18px language controls with at least 44px click targets in the green top bar. Do not add a separate language row beneath the main navigation. Preserve existing routes, source captures and original report/poster files.

Use the supplied copy, attachment, or source link for facts. Read linked sources before relying on them. Ask only for consequential missing facts such as an unknown event time or attribution; continue independent preparation. Do not invent dates, speakers, locations, author names, registration availability or official English personal names. Keep verified names unchanged when no English name is supplied.

## Add or update an event

Use for workshops, sharing meetings, conferences, retreats, mission trips with event details, posters, registration information, rescheduling or cancellation. News coverage after an event belongs in `cmi-add-news` or `cmi-add-article` unless the user asks to update the event itself.

1. Extract confirmed title, start/end date and time, timezone, venue/address or online attendance link, organizer/speaker, descriptive copy, poster, registration URL/deadline and status. Use `America/Toronto` for a confirmed Toronto event; do not apply that timezone to Cambodia or another location without evidence. Ask for an unknown critical detail; prepare all confirmed material meanwhile. Compare dates against the current time and distinguish upcoming, past, cancelled and registration-closed states. A past event is not evidence that registration was cancelled; an absent registration URL is not evidence that registration is open.
2. Inspect `eventsCards()`, `events()` and the `/event-details/` rendering branch in `scripts/build.mjs` before implementation. The October 2026 site indexes two `/近期活动` poster images with hard-coded titles: appending a third image alone produces wrong labels. All `/event-details/` pages are currently labelled archived and registration closed. Never put an upcoming event through that branch unchanged.
3. For additional events, make homepage cards and the main events listing read from the same explicit event metadata, adapting the existing template as needed. Use stable event IDs rather than new positional indexes; preserve existing `#event-1` and `#event-2` links. A practical new event model has `id`, `path`, `title`, `description`/body blocks, `start`, `end`, `timezone`, `venue`, `address`, `registrationUrl`, `registrationDeadline`, `status`, `poster` and provenance. Omit unconfirmed optional values. Store the model in a clearly named content source only after checking whether the repository already has one; do not assume `content/events.json` exists.
4. Give a new event a stable `/event-details/<slug>` page and keep the required `content/site.json.pages` record (`url`, `path`, `title`, `sourceText`, `blocks`, `images`, `links`, `ordered`) consistent with the event source. Avoid competing copies of dates or titles: let shared metadata feed cards, listing, detail page, search and archive. Render date/time and timezone visibly in all languages; exact numeric times, street addresses and destination URLs remain unchanged by translation.
5. Show confirmed actionable registration links and deadlines on upcoming events. The existing contact form only opens the visitor's email draft; it is not a working registration system. Do not create a fake RSVP/registration form, imply the website records attendance, or submit registrations during verification. Keep external registration links external, with safe new-tab attributes where used. Give cancellation/rescheduling notices prominence and preserve the old route.
6. Preserve every original poster and archived detail page. Keep the source placeholder `/event-details/event-1` marked `noindex`. Make actual past-event labels status-aware and keep archived events discoverable; do not delete them to clean up the homepage. Ensure new events appear in `/近期活动/`, appropriate homepage cards, detail pages, archive, search and sitemap. Both root `/` and `/home/` use the homepage template.
7. New event copy, poster descriptions, venue labels and status/registration messages need English dictionary entries and Simplified Chinese conversion. The existing English source-language notice covers `/post/`, `/event-details/` and `/近期活动`; preserve it. For image-only posters, add confirmed key details as translated readable text so visitors do not need to decipher small embedded text.

## Three languages, media and validation

- Follow the locale contract in root `AGENTS.md`: Traditional Chinese at `/` (`zh-Hant-CA`, default), Simplified Chinese at `/zh-hans/` (`zh-Hans-CA`), and English at `/en/` (`en-CA`). Keep stable route slugs across languages and use `localizedPath()` rather than hand-building translated URLs. Preserve correct document `lang`, canonical URL, all three `hreflang` alternates and Traditional Chinese `x-default`.
- Keep the visible labels exactly `繁體`, `简体`, and `EN`, with the current language marked by `aria-current`. Switching must preserve the same page, query string and section hash; internal navigation, archive links and search results must retain the selected locale. Include page descriptions, captions, accessibility labels and new runtime messages in translation coverage. Review OpenCC output for proper names and terminology; do not translate identifiers, external destinations or contact values.
- Author new editable copy in Traditional Chinese. Add English translations in `content/locales/en.json`; keys match `traditional(text.trim().replace(/\s+/g, ' '))` from `scripts/locales.mjs`. Translate each actual text node and translated attribute, including title, author if Chinese, alt text, category and new interface messages. Existing numeric/date rules can handle their supported formats. A missing English translation is a build error; keep this safeguard. Simplified Chinese is generated by OpenCC.
- Store authorized JPG/JPEG/PNG originals in `assets/images/` without overwriting existing files. Add an accurate `alt`; generate matching `-480.webp` and `-960.webp` previews with `scripts/optimize-images.py` using a Python environment with Pillow. Inspect the diff: this helper processes all originals, so retain unrelated derivatives if bytes change unnecessarily. Record genuine remote provenance in `site.assets` when there is a remote source; do not invent a Wix URL for an attachment.
- Follow `assets/media.css` and `content/image-layout.json` for image presentation. Document/poster thumbnails use `contain`; photo crops use reviewed `focalPoint: [x, y]` percentages, with `fit: "contain"` for collages, wide group photos or artwork when a crop would lose content. The shared `image()` helper accepts a `presentation` override; do not treat a new article photo cover as a document automatically. Preserve full reading images and original zoom links, keep captions/reading labels outside their image, and respect reduced-motion preferences.
- Original report/poster images remain in their source language. Preserve the English original-language notice and image enlarging. Add readable translated text for important information supplied only in images; inspect/transcribe the image and flag illegible details rather than guessing. Use the PDF skill if a PDF requires extraction or rendering.
- Build once before regenerating fonts so all generated languages enter the font corpus. When new characters need coverage, run `scripts/prepare-brand.py` in an isolated Python environment with `fonttools[woff]`, then rebuild to refresh font preloads and asset hashes. That script also recreates unused SVG logo proposals: never replace the currently approved site logo with them.
- Run `npm ci` when dependencies are missing or the lockfile changed, then `npm run build` and `npm run check`. The original validator asserts exactly 41 pages and 16 posts and prints fixed counts. When adding records, replace those stale totals/logs with accurate dynamic totals plus preservation checks for pre-edit routes and original media. Keep all per-page, translation, search, link and anchor checks; do not bypass validation or merely increase totals to conceal deletion. Preserve historical capture metadata (`capturedAt`, initial `routeCount`) rather than pretending new copy was captured from Wix.
- Verify the new entry in all three page versions, relevant listings, localized search and sitemap. Browser-check desktop and phone layouts, original-image zoom where applicable, and language switching on the new page. Retain the selected page/query/section. Use the available computer-use browser tooling; stop only a preview server you started and close temporary tabs.

Confirm that Pages built the merged commit, then verify the new route and affected listings/search in all three languages on the published origin, including correct visible content and working images.
